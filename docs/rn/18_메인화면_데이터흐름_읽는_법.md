# 메인화면 데이터흐름 읽는 법

이 문서는 Dogether RN 프로젝트의 메인 화면이 데이터를 어떻게 가져오고, 가공하고, 화면에 보여주는지 읽기 위한 문서입니다.

메인 화면은 단순히 투두 목록만 보여주는 화면이 아닙니다.

여기에는 다음 흐름이 같이 들어 있습니다.

```txt
그룹 목록 조회
마지막 선택 그룹 복원
현재 그룹 결정
날짜 이동
내 투두 조회
투두 상태 필터링
하단 패널 상태 결정
투두 작성 화면 이동
인증 화면 이동
인증 상세 화면 이동
그룹 선택 bottom sheet
랭킹/마이페이지 이동
```

처음 보면 한 화면에 너무 많은 일이 있는 것처럼 보이지만, 실제 구조는 꽤 잘 나뉘어 있습니다.

## 1. 먼저 전체 그림

메인 화면의 큰 데이터 흐름은 이렇습니다.

```txt
MainScreen
  |
  v
useMainScreen
  |
  +-- useMainStore            // 선택 그룹, 날짜 offset, 필터 같은 UI 상태
  |
  +-- useGroupsQuery          // 서버/mock에서 그룹 목록 조회
  |
  +-- useMyTodosQuery         // 현재 그룹/날짜 기준 내 투두 조회
  |
  +-- helper functions        // 날짜/필터/패널 상태 계산
  |
  v
MainHeader + MainPanel + GroupSelectBottomSheet + ReviewToast
```

한 줄로 말하면:

```txt
useMainScreen이 서버 상태와 UI 상태를 모아서 MainScreen이 바로 그릴 수 있는 값으로 정리한다.
```

## 4. MainScreen의 역할

파일:

```txt
src/screens/main/MainScreen.tsx
```

MainScreen은 실제 화면 컴포넌트입니다.

역할은 크게 네 가지입니다.

```txt
1. useMainScreen에서 화면에 필요한 값 받기
2. query 에러 처리
3. Header/Panel/BottomSheet/Toast 렌더링
4. 버튼 이벤트를 store action 또는 router에 연결
```

MainScreen은 데이터 계산을 많이 하지 않습니다.

계산은 대부분 `useMainScreen` 안에 있습니다.

## 5. MainScreen이 useMainScreen에서 받는 값

코드:

```ts
const {
  groupsQuery,
  todosQuery,
  currentGroup,
  filteredTodos,
  visibleTodos,
  dateOffset,
  queryDate,
  filter,
  formattedDate,
  canGoPast,
  canGoFuture,
  sheetStatus,
  activeFilterEmptyText,
} = useMainScreen();
```

이 값들을 분류하면 다음과 같습니다.

| 값 | 성격 |
| --- | --- |
| `groupsQuery`, `todosQuery` | React Query 결과 |
| `currentGroup` | 현재 선택된 그룹 |
| `visibleTodos` | 현재 그룹/날짜의 전체 투두 |
| `filteredTodos` | 현재 필터가 적용된 투두 |
| `dateOffset` | 오늘 기준 날짜 offset |
| `queryDate` | API 요청용 날짜 문자열 |
| `formattedDate` | 화면 표시용 날짜 문자열 |
| `filter` | 현재 투두 필터 |
| `canGoPast`, `canGoFuture` | 날짜 이동 가능 여부 |
| `sheetStatus` | 하단 패널 상태 |
| `activeFilterEmptyText` | 필터 결과가 비었을 때 문구 |

즉 MainScreen은 이미 정리된 ViewModel 값을 받아서 JSX에 꽂습니다.

## 7. 메인 화면의 상태는 두 종류다

메인 화면 데이터는 크게 두 종류로 나뉩니다.

| 종류 | 담당 | 예시 |
| --- | --- | --- |
| 서버 상태 | React Query | 그룹 목록, 내 투두 목록 |
| UI 상태 | Zustand | 선택 그룹, 날짜 offset, 필터 |

이 프로젝트에서 중요한 원칙:

```txt
서버에서 오는 데이터는 React Query가 맡고,
화면 조작 상태는 Zustand가 맡는다.
```

## 12. setSelectedGroupId

코드:

```ts
setSelectedGroupId: (selectedGroupId) => {
  saveLastSelectedGroupId(selectedGroupId);
  set({ selectedGroupId, dateOffset: 0, filter: 'all', sheetExpanded: false });
}
```

그룹을 바꿀 때 하는 일:

```txt
1. MMKV에 마지막 선택 그룹 저장
2. selectedGroupId 변경
3. dateOffset을 오늘로 초기화
4. filter를 전체로 초기화
5. sheetExpanded를 false로 초기화
```

그룹이 바뀌면 이전 그룹에서 보던 날짜/필터 상태를 그대로 가져가면 어색합니다.

그래서 같이 초기화합니다.

## 13. 날짜 이동 상태

코드:

```ts
dateOffset: 0
```

주석:

```ts
// 0은 오늘, -1은 어제, -2는 그저께입니다. 미래 이동은 0까지만 허용됩니다.
```

의미:

| `dateOffset` | 의미 |
| --- | --- |
| `0` | 오늘 |
| `-1` | 어제 |
| `-2` | 그저께 |

미래 날짜로는 이동하지 않습니다.

현재 날짜보다 과거만 볼 수 있고, 과거에서 다시 오늘까지 돌아올 수 있습니다.

## 14. movePast와 moveFuture

코드:

```ts
movePast: () => set((state) => ({ dateOffset: state.dateOffset - 1, filter: 'all' })),
moveFuture: () => set((state) => ({ dateOffset: state.dateOffset + 1, filter: 'all' })),
```

읽는 법:

```txt
과거로 이동하면 dateOffset을 -1 한다.
미래 방향으로 이동하면 dateOffset을 +1 한다.
날짜를 바꾸면 filter는 all로 초기화한다.
```

예:

```txt
오늘: 0
어제로 이동: -1
그저께로 이동: -2
다시 미래 방향: -1
다시 미래 방향: 0
```

## 19. 선택 그룹 보정 effect

코드:

```ts
useEffect(() => {
  if (!groupsQuery.data?.length) {
    if (selectedGroupId !== null) {
      setSelectedGroupId(null);
    }
    return;
  }

  if (!currentGroup) {
    setSelectedGroupId(groupsQuery.data[0].id);
  }
}, [currentGroup, groupsQuery.data, selectedGroupId, setSelectedGroupId]);
```

이 effect는 서버 그룹 목록이 바뀐 뒤 선택 그룹이 유효한지 보정합니다.

상황별로 보면:

| 상황 | 동작 |
| --- | --- |
| 그룹 목록이 비어 있음 | `selectedGroupId`를 `null`로 정리 |
| 저장된 선택 그룹이 목록에 없음 | 첫 번째 그룹 id로 보정 |
| 선택 그룹이 유효함 | 아무것도 하지 않음 |

예:

```txt
마지막 선택 그룹 id = 101
서버 그룹 목록 = [102, 103]
-> 101은 더 이상 없음
-> selectedGroupId를 102로 보정
```

## 20. 왜 선택 그룹 보정이 필요할까?

선택 그룹은 MMKV에 저장됩니다.

하지만 서버 그룹 목록은 언제든 바뀔 수 있습니다.

예:

```txt
이전에 그룹 101을 선택함
앱을 껐다 켬
그 사이 그룹 101에서 탈퇴됨
MMKV에는 101이 남아 있음
서버 목록에는 101이 없음
```

이때 보정하지 않으면 없는 그룹을 기준으로 투두를 조회하려고 할 수 있습니다.

그래서 `useEffect`에서 정리합니다.

## 21. 날짜 이동 가능 범위 계산

파일:

```txt
src/hooks/useMainScreen.ts
```

코드:

```ts
const canGoPast = Math.abs(dateOffset) < getPastOffsetLimit(currentGroup);
const canGoFuture = dateOffset < 0;
```

의미:

| 값 | 의미 |
| --- | --- |
| `canGoPast` | 더 과거 날짜로 갈 수 있는지 |
| `canGoFuture` | 오늘 방향으로 돌아올 수 있는지 |

`canGoFuture`는 단순합니다.

```txt

dateOffset이 0이면 false
```

오늘보다 미래로는 가지 않습니다.

## 22. getPastOffsetLimit

코드:

```ts
function getPastOffsetLimit(group: Group | undefined) {
  const startDate = parseDate(group?.startDate);
  if (!startDate) {
    return 0;
  }

  const today = startOfDay(new Date());
  const groupStart = startOfDay(startDate);
  const diff = Math.floor((today.getTime() - groupStart.getTime()) / (1000 * 60 * 60 * 24));
  return Math.max(0, diff);
}
```

이 함수는 그룹 시작일보다 더 과거로 가지 못하게 제한합니다.

예:

```txt
오늘이 5월 27일
그룹 시작일이 5월 24일
diff = 3
-> 최대 3일 전까지만 이동 가능
```

즉:

```txt
그룹이 시작되기 전 날짜의 투두는 볼 필요가 없다.
```

## 25. 왜 queryKey에 groupId와 date가 들어갈까?

투두 목록은 그룹과 날짜에 따라 다릅니다.

```txt
그룹 101의 2026-05-27 투두
```

## 26. enabled가 있는 이유

코드:

```ts

queryFn: () => challengeGroupUseCase.getMyTodos(groupId!, date),
```

`groupId`가 아직 없을 수 있습니다.

예:

```txt

-> currentGroup 없음
-> groupId 없음
```

이때 투두 query를 실행하면 안 됩니다.

그래서:

```txt

```

합니다.

`groupId!`는 "enabled 때문에 여기서는 groupId가 있다고 볼 수 있다"는 TypeScript 힌트입니다.

## 33. getSheetStatus 읽기

코드:

```ts
function getSheetStatus(group: Group | undefined, dateOffset: number, todos: Todo[]): MainSheetStatus {
  if (!group) {
    return 'createTodo';
  }

  if (group.status === 'dDay' && dateOffset === 0) {
    return 'done';
  }

  if (dateOffset === 0 && todos.length === 0) {
    return 'createTodo';
  }

  if (dateOffset === 0) {
    return 'certificateTodo';
  }

  if (dateOffset < 0 && todos.length === 0) {
    return 'emptyList';
  }

  return 'todoList';
}
```

판단 순서:

| 조건 | 결과 |
| --- | --- |
| 그룹 없음 | `createTodo` |
| 오늘이고 그룹 상태가 `dDay` | `done` |
| 오늘이고 투두 없음 | `createTodo` |
| 오늘이고 투두 있음 | `certificateTodo` |
| 과거이고 투두 없음 | `emptyList` |
| 그 외 | `todoList` |

```ts
}
```

에러 처리 방식:

| 에러 variant | 처리 |
| --- | --- |
| `alert` | 모달 표시 후 닫으면 로그아웃 + 온보딩 이동 |
| 그 외 | 전체 화면 에러 + 다시 시도 |

다시 시도는 실패한 query만 refetch합니다.

## 55. 투두 작성 후 메인 데이터 갱신

투두 작성 화면은 19번 문서에서 자세히 다루겠지만, 메인 화면과 연결되는 핵심은 query invalidation입니다.

투두를 저장하면 보통:

```txt
['todos', groupId, date]
또는 ['todos'] 계열 query 무효화
```

를 통해 메인 화면의 투두 목록을 다시 읽게 만듭니다.

메인 화면은 `useMyTodosQuery`를 통해 query cache를 보고 있으므로, invalidation 후 새 목록이 들어오면 자동으로 다시 렌더링됩니다.

---

## 56. 인증 후 메인 데이터 갱신

인증 화면도 메인 투두 query와 연결됩니다.

미인증 투두를 인증하면:

```txt
WAIT_CERTIFICATION
-> WAIT_APPROVAL
```

상태가 바뀝니다.

인증 제출 후 관련 `todos` query가 무효화되면 메인 화면의 `useMyTodosQuery`가 새 데이터를 받고, 해당 row는 더 이상 "인증하기" 버튼이 아니라 검사 대기 상태로 보입니다.

이 흐름은 19번 문서에서 더 자세히 보면 됩니다.

## 63. 초보자가 자주 헷갈리는 부분

### 63-1. selectedGroupId가 서버 데이터인가?

아닙니다.

`selectedGroupId`는 클라이언트 UI 상태입니다.

그룹 목록은 서버/React Query가 들고 있고, 그중 어떤 그룹을 보고 있는지는 Zustand가 들고 있습니다.

### 63-2. 필터를 바꾸면 API를 다시 호출하나?

아닙니다.

필터는 클라이언트에서 `visibleTodos.filter(...)`로 처리합니다.

### 63-3. 날짜를 바꾸면 API를 다시 호출하나?

합니다.

`queryDate`가 바뀌고, `useMyTodosQuery`의 `queryKey`가 바뀌기 때문입니다.

### 63-4. 그룹을 바꾸면 날짜/필터가 왜 초기화되나?

이전 그룹에서 보던 UI 상태가 새 그룹에 섞이지 않게 하기 위해서입니다.

### 63-5. WAIT_CERTIFICATION은 왜 필터가 없나?

현재 필터는 인증 이후 상태 중심입니다.

미인증 투두는 `all`에서 보이고, 별도 필터 버튼은 없습니다.

### 63-6. MainScreen이 왜 이렇게 많은 props를 MainPanel에 넘기나?

MainPanel을 화면 하단 UI 전용 컴포넌트로 분리했기 때문입니다.

계산은 `useMainScreen`, 이벤트 action은 `MainScreen`, 렌더링은 `MainPanel`로 나뉘어 있습니다.

## 67. 마지막으로 한 번에 정리

메인 화면 데이터 흐름의 핵심은 이것입니다.

```txt
MainScreen은 UI 조립과 에러 처리를 맡는다.
useMainScreen은 서버 상태와 UI 상태를 조합해 ViewModel 값을 만든다.
mainStore는 선택 그룹, 날짜 offset, 필터를 가진다.
useGroupsQuery는 그룹 목록을 가져온다.
currentGroup은 selectedGroupId 기준으로 계산하고, 유효하지 않으면 보정한다.
useMyTodosQuery는 currentGroup과 queryDate 기준으로 내 투두를 가져온다.
visibleTodos는 전체 투두, filteredTodos는 필터 적용 결과다.
sheetStatus는 오늘/과거/투두 유무/그룹 종료 상태로 결정된다.
TodoRow는 인증 작성 또는 인증 상세 이동을 담당한다.
```

한 줄로 줄이면:

```txt
Dogether RN의 메인 화면은 React Query의 서버 데이터와 Zustand의 UI 상태를 useMainScreen에서 합쳐서, Header/Panel/TodoRow가 바로 렌더링할 수 있게 만든 구조다.
```
