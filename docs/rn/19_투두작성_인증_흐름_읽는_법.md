# 투두작성 인증 흐름 읽는 법

이 문서는 Dogether RN 프로젝트에서 투두를 작성하고, 작성한 투두를 인증하는 흐름을 읽기 위한 문서입니다.

18번 메인화면 문서에서 본 것처럼 메인 화면은 투두 목록을 보여주고, 사용자를 두 가지 작성 흐름으로 보냅니다.

```txt
투두가 없거나 추가하고 싶음
-> /todo-write
-> 투두 작성

미인증 투두를 인증하고 싶음
-> /certify
-> 인증 사진 선택
-> /certify-content
-> 인증 내용 입력
-> 인증 제출
```

이 문서에서는 위 두 흐름을 이어서 봅니다.

---

## 1. 이 문서의 목표

이 문서를 읽고 나면 다음을 알 수 있어야 합니다.

```txt
메인 화면에서 투두 작성 화면으로 이동하는 흐름
TodoWriteScreen이 기존 투두와 새 draft를 구분하는 방식
투두 저장 시 createTodos가 호출되는 흐름
저장 후 React Query 캐시를 갱신하는 방식
메인 화면에서 인증 화면으로 이동할 때 넘기는 params
CertificationImageScreen이 route params로 draft를 시작하는 방식
사진 선택/촬영과 권한 처리 흐름
CertificationContentScreen이 최종 인증 API를 호출하는 방식
S3 업로드와 인증 API 호출 순서
인증 후 메인/인증목록/통계 query가 갱신되는 방식
```

## 6. 투두 추가 버튼이 보이는 조건

코드:

```tsx
dateOffset === 0 && filter === 'all' && visibleTodos.length < 10
```

의미:

```txt

필터가 전체여야 한다.
```

과거 날짜에서는 투두를 추가하지 못합니다.

필터가 걸린 상태에서는 현재 전체 개수를 오해할 수 있으므로 추가 버튼을 숨깁니다.

## 8. TodoDraftItem 타입

파일:

```txt
src/screens/todoWrite/TodoWriteScreen.tsx
```

코드:

```ts
type TodoDraftItem = {
  id: number;
  content: string;
  locked: boolean;
  status: Todo['status'];
};
```

`TodoDraftItem`은 투두 작성 화면 안에서 쓰는 임시 모델입니다.

| 필드 | 의미 |
| --- | --- |
| `id` | 임시 또는 서버 투두 id |
| `content` | 투두 내용 |
| `locked` | 이미 저장되어 수정/삭제할 수 없는지 |
| `status` | 투두 상태 |

핵심은 `locked`입니다.

---

## 9. locked의 의미

투두 작성 화면에는 기존 투두와 새로 입력한 draft가 같이 보일 수 있습니다.

```txt
기존 서버 투두
-> 이미 저장됨
-> 수정/삭제 불가
-> locked: true 또는 status에 따라 locked

새로 입력한 draft
-> 아직 저장 안 됨
-> 삭제 가능
-> locked: false
```

이 구분이 있어야 저장할 때 새로 추가한 항목만 서버로 보낼 수 있습니다.

## 14. 기존 투두 bootstrap

TodoWriteScreen 진입 시 오늘의 기존 투두를 불러옵니다.

코드:

```ts
useEffect(() => {
  let mounted = true;

  (async () => {
    const groups = await groupUseCase.getGroups();
    const fallbackGroupId = groups[0]?.id;
    const groupId = selectedGroupId ?? fallbackGroupId;

    if (!groupId) {
      if (mounted) {
        setIsBootstrapping(false);
      }
      return;
    }

    const existingTodos = await challengeGroupUseCase.getMyTodos(groupId, toQueryDate());
    if (mounted) {
      setTodos(
        existingTodos.map((todo) => ({
          id: todo.id,
          content: todo.content,
          locked: todo.status !== 'WAIT_CERTIFICATION',
          status: todo.status,
        })),
      );
      setIsBootstrapping(false);
    }
  })();

  return () => {
    mounted = false;
  };
}, [challengeGroupUseCase, groupUseCase, selectedGroupId]);
```

흐름:

```txt
그룹 목록 조회
-> selectedGroupId가 있으면 사용
-> 없으면 첫 번째 그룹 사용
-> 오늘 날짜로 내 투두 조회
-> TodoDraftItem[]으로 변환
-> todos state에 넣기
```

## 15. 기존 투두의 locked 규칙

코드:

```ts
locked: todo.status !== 'WAIT_CERTIFICATION'
```

의미:

```txt
WAIT_CERTIFICATION이면 아직 인증 전이므로 작성 목록에서 unlocked
그 외 WAIT_APPROVAL/APPROVED/REJECTED는 locked
```

주의할 점:

```txt
이미 인증했거나 검토가 끝난 투두는 작성 화면에서 삭제할 수 없다.
```

현재 코드에서는 `WAIT_CERTIFICATION` 기존 투두는 unlocked처럼 보일 수 있습니다.

저장 시에는 unlocked 항목을 contents로 보내므로, 이 동작을 읽을 때 주의해야 합니다.

## 20. draft 삭제

TodoWriteScreen에서 TodoDraftList에 넘기는 삭제 함수:

```ts
onRemove={(index) =>
  setTodos((current) =>
    current.filter((todo, currentIndex) => currentIndex !== index || todo.locked),
  )
}
```

읽는 법:

```txt
선택한 index의 항목이 unlocked이면 제거한다.
locked이면 제거하지 않는다.
```

조건을 다시 쓰면:

```txt
currentIndex !== index 이면 유지
또는 todo.locked 이면 유지
```

그래서 locked 항목은 삭제할 수 없습니다.

## 22. 투두 저장

코드:

```ts
const handleSaveTodos = async () => {
  try {
    const groups = await groupUseCase.getGroups();
    const fallbackGroupId = groups[0]?.id;
    const groupId = selectedGroupId ?? fallbackGroupId;
    if (!groupId) {
      setConfirmVisible(false);
      router.back();
      return;
    }

    await challengeGroupUseCase.createTodos(
      groupId,
      toQueryDate(),
      todos.filter((todo) => !todo.locked).map((todo) => todo.content),
    );
    await queryClient.invalidateQueries({ queryKey: ['todos'] });
    setConfirmVisible(false);
    router.back();
  } catch (error) {
    setConfirmVisible(false);
    setSubmitError(toAppError(error));
  }
};
```

저장 흐름:

```txt
그룹 id 결정
-> unlocked 투두만 content 배열로 변환
-> ChallengeGroupUseCase.createTodos()
-> todos query 무효화
-> modal 닫기
-> 이전 화면으로 돌아가기
```

```ts
async createTodos(_groupId: number, _date: string, contents: string[]): Promise<Todo[]> {
  try {
    await apiClient.post<ApiEnvelope<null>>(endpoints.challengeGroups.createTodos(_groupId), {
```

## 47. 인증 제출

```ts
const handleSubmit = async () => {
  if (!canSubmit || !draft.todoId || !draft.groupId || !draft.date || !draft.imageUri) {

  }

      draft.date,

  }
};
```

```txt
-> certifyTodo 호출
```

```txt
https://bucket.s3.../image.png?X-Amz-Signature=...
```

이 query string은 업로드 권한과 관련되어 있습니다.

앱/서버에 저장할 이미지 URL은 query string이 없는 형태가 더 적절합니다.

그래서 helper가 있습니다.

```ts
function stripQueryString(url: string) {
  const parsed = new URL(url);
  parsed.search = '';
  return parsed.toString();
}
```

업로드 후 반환하는 값:

```txt
https://bucket.s3.../image.png
```

## 58. Android URI 정규화

코드:

```ts
async function normalizeLocalImageUri(localUri: string) {
  if (
    Platform.OS !== 'android' ||
    (!localUri.startsWith('content://') && !localUri.startsWith('file://'))
  ) {
    return localUri;
  }

  const normalizedUri = `${cacheDirectory}certification-upload-${Date.now()}.jpg`;
  await FileSystem.copyAsync({
    from: localUri,
    to: normalizedUri,
  });

  return normalizedUri;
}
```

Android에서는 이미지 URI가 `content://` 형태일 수 있습니다.

이 URI는 업로드 과정에서 바로 다루기 어려울 수 있어 cache 파일로 복사합니다.

흐름:

```txt
content:// 또는 file:// URI
-> cacheDirectory에 복사
-> file URI처럼 다룰 수 있는 normalized URI 반환
```

## 68. 초보자가 자주 헷갈리는 부분

### 68-1. 투두 작성 화면의 todos는 서버 데이터인가?

처음에는 서버/mock에서 가져온 기존 투두를 담습니다.

그 뒤 사용자가 추가한 draft도 같은 배열에 섞입니다.

그래서 `locked`로 기존/신규를 구분합니다.

### 68-2. 저장 버튼을 누르면 모든 todos를 서버로 보내나?

아닙니다.

`locked`가 아닌 항목의 content만 보냅니다.

### 68-3. 인증 사진 화면에서 선택한 imageUri는 어디에 저장되나?

`certificationDraftStore`의 `draft.imageUri`에 저장됩니다.

### 68-4. 인증 내용 화면은 route params를 다시 읽나?

아닙니다.

내용 화면은 `certificationDraftStore`에서 draft를 읽습니다.

### 68-5. API 인증에서 서버에 local imageUri를 보내나?

아닙니다.

먼저 `uploadImageToS3(localUri)`로 S3에 올리고, 그 결과 URL을 인증 API에 보냅니다.

### 68-6. mock 인증도 S3 업로드를 하나?

아닙니다.

mock repository는 local mediaUrl을 그대로 mock todo에 저장합니다.

### 68-7. 인증 후 왜 여러 query를 무효화하나?

인증 하나가 메인 목록, 인증 목록, 통계에 모두 영향을 줄 수 있기 때문입니다.

## 72. 마지막으로 한 번에 정리

투두 작성 흐름의 핵심:

```txt
투두 작성은 한 화면 안에서 local state로 draft를 관리한다.
기존 투두와 새 draft는 locked로 구분한다.
저장할 때는 unlocked draft의 content만 createTodos로 보낸다.
저장 후 ['todos'] query를 무효화하고 이전 화면으로 돌아간다.
```

인증 흐름의 핵심:

```txt
인증은 사진 화면과 내용 화면으로 나뉜다.
route params로 인증 대상 정보를 받고, Zustand draft store에 저장한다.
사진 선택 후 imageUri를 draft에 저장한다.
내용 입력 후 certifyTodo를 호출한다.
API 모드에서는 이미지를 S3에 먼저 업로드한 뒤 인증 API를 호출한다.
성공 후 관련 query를 무효화하고 draft를 비운 뒤 main으로 돌아간다.
```

한 줄로 줄이면:

```txt
Dogether RN의 투두 작성은 local draft 저장 흐름이고, 인증은 route를跨는 draft store와 S3 업로드가 결합된 제출 흐름이다.
```
