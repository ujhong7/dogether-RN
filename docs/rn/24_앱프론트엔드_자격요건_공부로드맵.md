# 앱 프론트엔드 자격요건 공부로드맵

이 문서는 앱 프론트엔드 개발자 공고에서 자주 보이는 자격요건을 보고, 무엇을 공부해야 하는지 정리한 문서입니다.

예를 들어 이런 문구가 있다고 해봅니다.

```text
TypeScript(JavaScript) / 브라우저 동작에 깊은 이해를 갖춘 분
React, Vue.js 등의 모던 웹 프레임워크 활용에 능숙한 분
```

처음 보면 "나는 React Native를 하려는데 왜 브라우저랑 웹 프레임워크를 말하지?"라고 느낄 수 있습니다.

하지만 앱 프론트엔드, 특히 React Native 개발에서도 아래 기초는 그대로 중요합니다.

```text
JavaScript / TypeScript
-> 앱 로직을 쓰는 언어

React
-> React Native 화면을 구성하는 핵심 모델

브라우저 동작 원리
-> 프론트엔드 런타임, 이벤트, 네트워크, 렌더링을 이해하는 기본기

모던 웹 프레임워크
-> 컴포넌트, 상태, 라우팅, 서버 상태 관리 감각
```

---

## 1. 이 자격요건이 실제로 뜻하는 것

공고 문구를 조금 풀어보면 다음과 같습니다.

| 공고 문구 | 실제 의미 |
| --- | --- |
| TypeScript(JavaScript)에 깊은 이해 | 문법만 아는 것이 아니라 비동기, 타입, 런타임 동작을 이해 |
| 브라우저 동작에 깊은 이해 | DOM, 렌더링, 이벤트, 네트워크, 저장소, 보안 흐름을 이해 |
| React, Vue.js 등의 활용 | 컴포넌트 기반 UI와 상태 관리 패턴을 능숙하게 사용 |
| 모던 웹 프레임워크 | SPA, routing, server state, build, bundling 흐름을 이해 |

React Native 개발자에게도 이 요구사항이 중요한 이유는 간단합니다.

```text
React Native는 브라우저에서 실행되지는 않지만,
JavaScript/TypeScript와 React의 사고방식 위에서 앱을 만든다.
```

즉 RN을 잘하려면 RN 컴포넌트만 외우는 것보다, JS/TS와 React의 기초를 깊게 잡는 것이 더 오래 갑니다.

---

## 2. 전체 공부 지도

처음부터 너무 넓게 보면 지칩니다.

아래 순서로 보면 좋습니다.

```text
1. JavaScript 언어 기본기
2. TypeScript 타입 시스템
3. React 컴포넌트와 Hook
4. 브라우저 동작 원리
5. HTTP와 API 통신
6. 상태 관리와 서버 상태 관리
7. React Native / Expo로 확장
```

이 순서는 Dogether RN 프로젝트를 읽는 순서와도 잘 맞습니다.

```text
TS 문법
-> 컴포넌트
-> Hook
-> Query / Store
-> Repository / API
-> Expo / Native 실행
```

## 3. JavaScript에서 공부할 것

JavaScript는 React Native 앱 로직이 실행되는 언어입니다.

가장 먼저 아래 개념을 잡아야 합니다.

| 주제 | 왜 중요한가 |
| --- | --- |
| 변수와 함수 | 모든 로직의 기본 |
| 객체와 배열 | API 응답, 화면 데이터, 상태 대부분이 객체/배열 |
| 구조 분해 할당 | props, hook 반환값을 읽을 때 자주 사용 |
| spread/rest 문법 | 기존 상태를 복사하고 일부만 바꿀 때 사용 |
| `map`, `filter`, `reduce` | 목록 화면과 데이터 가공에 자주 사용 |
| closure | hook, event handler, callback 이해에 필요 |
| scope | 값이 어디에서 살아 있는지 이해 |
| module import/export | 파일 간 의존성 이해 |
| Promise | 비동기 API 호출 이해 |
| async/await | 서버 요청, storage 접근, SDK 호출 이해 |
| event loop | 비동기 코드 실행 순서 이해 |

예를 들어 RN 코드에서 이런 패턴을 자주 봅니다.

```ts
const currentGroup = groups.find((group) => group.id === selectedGroupId);
```

이 코드를 읽으려면 배열 메서드, arrow function, 객체 property 접근을 알아야 합니다.

또 이런 코드도 많습니다.

```ts
const handleSubmit = async () => {
  await mutation.mutateAsync(input);
  router.replace('/main');
};
```

이 코드를 읽으려면 `async/await`, 함수, mutation 흐름, 라우팅 호출을 함께 이해해야 합니다.

## 4. TypeScript에서 공부할 것

TypeScript는 JavaScript에 타입을 얹은 언어입니다.

처음에는 타입 문법이 귀찮아 보이지만, 프로젝트가 커질수록 화면, API, 상태의 약속을 지켜주는 역할을 합니다.

| 주제 | 왜 중요한가 |
| --- | --- |
| `type` | 앱 모델과 props 타입 정의 |
| `interface` | Repository contract 같은 객체 구조 정의 |
| union type | 상태값, route 결과, 성공/실패 모델 표현 |
| optional property | API 응답에 없을 수도 있는 값 표현 |
| generic | query, repository, 공통 응답 타입 이해 |
| function type | callback props, event handler 타입 정의 |
| `Pick`, `Omit` | 기존 타입에서 일부만 재사용 |
| `Record` | key-value 형태의 타입 정의 |
| `as const` | literal type 고정 |
| `unknown` | 외부 에러나 API 응답을 안전하게 다루기 |

Dogether RN에서는 이런 곳을 보면 TypeScript 감각을 익히기 좋습니다.

| 위치 | 볼 것 |
| --- | --- |
| `src/models` | 앱 내부 데이터 모델 |
| `src/services/repositories/contracts` | Repository interface |
| `src/types/api.ts` | API 관련 공통 타입 |
| `src/queries` | React Query hook 반환 타입 |
| `src/screens/**/components` | 컴포넌트 props 타입 |

TypeScript를 공부할 때 중요한 감각은 이것입니다.

```text
타입은 "지금 값이 무엇인가"보다
"이 값이 어떤 약속을 지켜야 하는가"를 표현한다.
```

## 5. React에서 공부할 것

React Native는 React로 화면을 만듭니다.

웹에서는 `div`, `button`, `input`을 쓰고, RN에서는 `View`, `Pressable`, `TextInput`을 쓰지만 핵심 구조는 같습니다.

| React 개념 | RN에서의 의미 |
| --- | --- |
| Component | 화면 조각 |
| Props | 부모가 자식에게 넘기는 입력값 |
| State | 화면이 기억하는 값 |
| JSX | UI를 선언하는 문법 |
| Hook | 함수형 컴포넌트에서 상태와 생명주기를 쓰는 방법 |
| Custom Hook | 화면 로직을 재사용 가능하게 분리 |
| Conditional Rendering | 상태에 따라 다른 UI 표시 |
| List Rendering | 배열 데이터를 화면 목록으로 표시 |
| Key | 목록 렌더링에서 항목을 구분 |
| Memoization | 불필요한 계산이나 렌더링 줄이기 |

먼저 익혀야 할 Hook은 아래입니다.

| Hook | 용도 |
| --- | --- |
| `useState` | 화면 내부 상태 |
| `useEffect` | 렌더링 이후 실행할 작업 |
| `useMemo` | 계산 결과 재사용 |
| `useCallback` | 함수 재사용 |
| custom hook | 화면 로직 분리 |

React를 읽을 때 가장 중요한 감각은 이것입니다.

```text
state가 바뀐다
-> component 함수가 다시 실행된다
-> JSX가 다시 계산된다
-> 바뀐 부분만 화면에 반영된다
```

이 감각이 잡히면 RN 화면도 훨씬 편하게 읽힙니다.

## 6. 브라우저 동작에서 공부할 것

공고의 "브라우저 동작에 깊은 이해"는 단순히 HTML/CSS를 안다는 뜻이 아닙니다.

브라우저가 화면을 그리고, 이벤트를 처리하고, 서버와 통신하고, 데이터를 저장하는 전체 흐름을 이해한다는 뜻입니다.

| 주제 | 의미 |
| --- | --- |
| DOM | HTML을 트리 구조로 표현한 것 |
| CSSOM | CSS를 브라우저가 이해하는 구조로 만든 것 |
| Rendering Pipeline | style, layout, paint, composite 흐름 |
| Reflow/Layout | 요소 크기와 위치를 다시 계산하는 작업 |
| Repaint | 색상, 그림자, 배경 등을 다시 그리는 작업 |
| Event Bubbling/Capturing | 이벤트가 부모/자식 사이에서 전달되는 방식 |
| Event Loop | 비동기 작업 실행 순서 |
| Fetch/XHR | 서버 API 호출 방식 |
| CORS | 다른 도메인 API 호출을 제한하는 브라우저 보안 정책 |
| Cookie | 브라우저가 서버와 주고받는 작은 저장값 |
| localStorage/sessionStorage | 브라우저 로컬 저장소 |
| Cache | 네트워크 응답과 asset 재사용 |

React Native는 DOM을 쓰지는 않습니다.

하지만 아래 개념들은 RN에서도 거의 그대로 도움이 됩니다.

```text
event loop
비동기 API 호출
HTTP 요청/응답
캐시
상태 변경과 렌더링 비용
로컬 저장소
성능 최적화
```

브라우저를 공부하는 이유는 웹만 하기 위해서가 아니라, 프론트엔드 런타임이 어떻게 움직이는지 이해하기 위해서입니다.

## 7. HTTP와 API 통신에서 공부할 것

앱 프론트엔드는 결국 서버와 데이터를 주고받습니다.

아래 내용은 꼭 알아야 합니다.

| 주제 | 왜 중요한가 |
| --- | --- |
| HTTP method | GET, POST, PUT, PATCH, DELETE 구분 |
| status code | 200, 400, 401, 403, 404, 500 의미 |
| request header | 인증 토큰, content type 전달 |
| response body | 서버가 내려주는 데이터 |
| query parameter | 목록 조회, 필터, 페이지네이션 |
| path parameter | 특정 리소스 식별 |
| access token | 로그인 인증 |
| refresh token | 세션 연장 |
| multipart upload | 이미지/파일 업로드 |
| timeout | 서버 응답 지연 처리 |
| error handling | 서버 에러를 앱 에러로 변환 |

Dogether RN에서는 아래 흐름을 보면 좋습니다.

```text
Screen
-> Hook
-> Query / Mutation
-> UseCase
-> Repository
-> apiClient
-> server
```

특히 `src/services/api/client.ts`는 공통 API client라서, 프론트엔드 네트워크 흐름을 읽기 좋은 파일입니다.

## 8. 상태 관리에서 공부할 것

프론트엔드에서 상태 관리는 아주 중요합니다.

먼저 상태를 종류별로 나누는 감각이 필요합니다.

| 상태 종류 | 예시 | Dogether RN에서 |
| --- | --- | --- |
| 화면 내부 상태 | input 값, modal 열림 | `useState` |
| 전역 UI 상태 | 선택 그룹, 날짜 offset | Zustand |
| 서버 상태 | 그룹 목록, 투두 목록, 랭킹 | React Query |
| 영구 저장 상태 | 로그인 세션, 선택 그룹 | MMKV |

초보 때는 모든 상태를 하나의 store에 넣고 싶어지지만, 그러면 점점 복잡해집니다.

이렇게 나누면 읽기 쉽습니다.

```text
서버에서 가져온 데이터
-> React Query

앱이 들고 있어야 하는 UI 선택값
-> Zustand

화면 하나에서만 쓰는 값
-> useState

앱을 껐다 켜도 남아야 하는 값
-> MMKV
```

## 9. React와 Vue는 둘 다 해야 할까?

공고에 `React, Vue.js 등의`라고 적혀 있으면 보통 둘 다 완벽히 하라는 뜻은 아닙니다.

대부분은 "모던 프론트엔드 프레임워크를 써본 사람"이라는 뜻에 가깝습니다.

React를 깊게 공부하면 우선 충분합니다.

나중에 Vue를 볼 때는 차이를 비교하면 됩니다.

| 기준 | React | Vue |
| --- | --- | --- |
| UI 작성 | JSX 중심 | template 중심 |
| 상태 | hook, state | ref, reactive |
| 파생값 | useMemo | computed |
| 생명주기 | useEffect | lifecycle hook |
| 컴포넌트 입력 | props | props |
| 이벤트 전달 | callback props | emit |

핵심은 프레임워크 이름보다 아래 감각입니다.

```text
컴포넌트로 화면을 쪼갠다.
상태가 바뀌면 화면이 바뀐다.
부모와 자식이 props/event로 통신한다.
서버 데이터와 UI 상태를 구분한다.
```

## 10. RN 개발자 기준 공부 우선순위

React Native 앱 개발자를 목표로 한다면 우선순위는 이렇게 잡는 것이 좋습니다.

| 우선순위 | 공부할 것 | 이유 |
| --- | --- | --- |
| 1 | JavaScript 비동기와 배열/객체 | 앱 로직 대부분의 기본 |
| 2 | TypeScript 타입 모델링 | API, props, repository 구조 이해 |
| 3 | React component와 hook | RN 화면 구조의 핵심 |
| 4 | React Query / Zustand | 서버 상태와 UI 상태 분리 |
| 5 | HTTP/API | 실제 서버 연동 |
| 6 | 브라우저 이벤트 루프와 렌더링 | 프론트엔드 깊이 확보 |
| 7 | Expo/RN native 경계 | iOS/Android 실행, 권한, SDK 이해 |
| 8 | Vue 또는 다른 프레임워크 | 비교 감각 확보 |

처음부터 브라우저 렌더링 파이프라인을 너무 깊게 파기보다, JS/TS와 React를 먼저 잡고 그 다음 브라우저 원리를 붙이는 것이 좋습니다.

## 11. Dogether RN으로 연습하는 방법

공부한 내용을 Dogether RN에서 바로 확인하려면 아래처럼 보면 됩니다.

| 공부 주제 | 프로젝트에서 볼 위치 |
| --- | --- |
| TypeScript 모델 | `src/models` |
| Props 타입 | `src/screens/**/components` |
| React component | `src/screens` |
| Custom Hook | `src/hooks` |
| React Query | `src/queries` |
| Zustand | `src/stores` |
| API 통신 | `src/services/api` |
| Repository pattern | `src/services/repositories` |
| 환경 변수 | `src/config/env.ts` |
| Expo 설정 | `app.config.ts` |
| 라우팅 | `app` |

예를 들어 메인 화면을 공부한다면 아래 순서로 보면 좋습니다.

```text
app/main.tsx
-> src/screens/main/MainScreen.tsx
-> src/hooks/useMainScreen.ts
-> src/queries/useMyTodosQuery.ts
-> src/services/usecases
-> src/services/repositories
```

이 한 줄기를 따라가면 React, TypeScript, 상태 관리, API 흐름을 한 번에 볼 수 있습니다.

## 13. 추천 학습 순서

현실적인 순서는 아래처럼 잡으면 좋습니다.

```text
1주차
-> JavaScript 문법, 배열 메서드, async/await

2주차
-> TypeScript type/interface/union/generic

3주차
-> React component, props, state, useEffect

4주차
-> custom hook, React Query, Zustand

5주차
-> HTTP, Axios, API error handling
```
