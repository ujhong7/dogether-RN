# 리뷰 랭킹 통계 흐름 읽는 법

이 문서는 Dogether RN 프로젝트에서 리뷰, 랭킹, 통계, 인증 목록 화면의 데이터 흐름을 읽기 위한 문서입니다.

이 네 영역은 서로 따로 떨어져 있는 것처럼 보이지만, 실제로는 인증 데이터 하나를 중심으로 연결되어 있습니다.

```txt
사용자가 투두 인증
-> 다른 사용자가 리뷰
-> 리뷰 결과가 인증 목록/통계/랭킹에 반영
-> 랭킹에서 다른 멤버 인증을 열어 읽음 처리
```

즉 19번 문서에서 본 인증 제출 이후의 후속 흐름이라고 보면 좋습니다.

---

## 1. 이 문서의 목표

이 문서를 읽고 나면 다음을 알 수 있어야 합니다.

```txt
앱 시작 시 왜 리뷰 화면으로 갈 수 있는지
리뷰 대기 목록 query와 제출 흐름
리뷰 완료 후 메인 토스트가 뜨는 흐름
랭킹 화면이 현재 그룹 기준으로 데이터를 가져오는 방식
랭킹에서 멤버 인증 상세를 여는 흐름
랭킹 인증 상세에서 읽음 처리하는 방식
통계 화면이 그룹과 통계 query를 조합하는 방식
인증 목록 화면의 정렬/필터/상세 이동 흐름
인증 제출/리뷰/탈퇴 후 어떤 query들이 무효화되는지
```

```txt
-> 로그인 여부 확인

```

즉 로그인했고 가입 그룹도 있는데, 아직 검사해야 할 인증이 있으면 앱은 `/review`로 이동할 수 있습니다.

이 정책 때문에 리뷰 화면은 단순히 사용자가 직접 누르는 화면이 아니라 앱 진입 분기와 연결됩니다.

## 13. currentReview와 canSubmit

코드:

```ts
const currentReview = pendingReviewsQuery.data?.[0] ?? null;

  selectedResult === 'APPROVE'
    ? !isSubmitting
```

## 17. 리뷰 제출

파일:

```txt
src/hooks/useReviewScreen.ts
```

코드:

```ts
const submit = async () => {
  if (!currentReview || !selectedResult || !canSubmit) {
    return;
  }

  setIsSubmitting(true);
  try {
    await reviewUseCase.submitReview(currentReview.id, selectedResult, feedback.trim());
    await Promise.all([
      queryClient.invalidateQueries({ queryKey: ['pending-reviews'] }),
      queryClient.invalidateQueries({ queryKey: ['launch-flow'] }),
    ]);
    resetSelection();
  } finally {
    setIsSubmitting(false);
  }
};
```

흐름:

```txt
현재 리뷰/선택/제출 가능 여부 검사
-> submitReview 호출
-> pending-reviews query 무효화
-> launch-flow query 무효화
-> 선택 상태 초기화
```

`launch-flow`를 무효화하는 이유는 앱 시작 분기에서 pending review 여부를 보기 때문입니다.

```ts
        void queryClient.invalidateQueries({ queryKey: ['ranking', context.groupId] });
      }
    })
    .catch(() => {
      readTodoIdsRef.current.delete(currentTodo.id);
    });
}, ...);
```

흐름:

```txt
랭킹 source로 상세 진입
-> 현재 todo id 읽음 처리
-> 성공하면 ['ranking', groupId] 무효화
-> 실패하면 readTodoIdsRef에서 제거
```

이 덕분에 랭킹의 읽음 상태가 최신화됩니다.

```ts
export function filterCertificationItems(items: CertificationListItem[], filter: CertificationListFilter) {
  switch (filter) {
    case 'wait':
      return items.filter((item) => item.status === 'WAIT_APPROVAL');
    case 'approve':
      return items.filter((item) => item.status === 'APPROVED');
    case 'reject':
      return items.filter((item) => item.status === 'REJECTED');
    case 'all':
    default:
      return items;
  }
}
```

| filter | status |
| --- | --- |

| `approve` | `APPROVED` |

| `all` | 전체 |

## 57. 초보자가 자주 헷갈리는 부분

### 57-1. 리뷰 화면은 사용자가 직접 들어가는 화면인가?

직접 들어갈 수도 있지만, 핵심은 앱 시작 분기에서 자동으로 갈 수 있다는 점입니다.

pending review가 있으면 `/review`가 우선됩니다.

### 57-2. 리뷰 제출은 React Query mutation을 쓰나?

현재 코드는 `useMutation`이 아니라 hook 안의 async `submit` 함수로 처리합니다.

성공 후 직접 `invalidateQueries`를 호출합니다.

### 57-3. 랭킹에서 인증 상세를 열 때 route params를 쓰나?

핵심 데이터는 `certificationViewerStore`에 저장합니다.

상세 화면이 여러 todo를 넘겨보는 viewer이기 때문입니다.

### 57-4. 통계 필터나 그룹 선택은 서버 데이터인가?

그룹 목록과 통계는 서버 데이터지만, 어떤 그룹을 선택했는지는 Zustand UI 상태입니다.

### 57-5. 인증 목록 필터를 바꾸면 API를 다시 호출하나?

아닙니다.

필터는 클라이언트에서 `filteredSections`로 처리합니다.

정렬 기준을 바꾸면 query key가 바뀌므로 새 query가 실행될 수 있습니다.

### 57-6. 인증 제출 후 왜 통계와 인증 목록이 갱신되나?

인증 하나가 내 인증 목록과 통계 숫자에 영향을 주기 때문입니다.

## 59. 디버깅 체크리스트

리뷰가 이상할 때:

```txt
useLaunchFlowQuery가 review로 보내는가?
usePendingReviewsQuery 데이터가 있는가?
currentReview가 data[0]으로 잡히는가?
selectedResult와 feedback이 canSubmit 조건을 만족하는가?
submitReview가 성공하는가?
pending-reviews / launch-flow가 무효화되는가?
리뷰 완료 후 ReviewToast가 표시되는가?
```

랭킹이 이상할 때:

```txt
selectedGroupId와 currentGroup이 맞는가?
useRankingQuery가 enabled 되는가?
rankingQuery.data가 있는가?
historyReadStatus가 null이라 row가 비활성화된 것은 아닌가?
getMemberTodos가 성공하는가?
certificationViewerStore context가 source ranking으로 들어가는가?
readTodo 후 ranking query가 무효화되는가?
```

통계가 이상할 때:

```txt
groupsQuery가 성공했는가?
currentGroup이 있는가?
useStatisticsQuery가 enabled 되는가?
statisticsQuery.data.achievements가 있는가?
summary가 null인지 확인했는가?
그룹 선택 후 selectedGroupId가 바뀌는가?
```

인증 목록이 이상할 때:

```txt
sort 값이 무엇인가?
useCertificationListQuery queryKey가 바뀌는가?
sections에 item이 있는가?
filter 때문에 filteredSections가 비어 있는가?
openCertificationDetail에서 relatedItems가 잘 잡히는가?
viewerTodos가 Todo[] 형태로 만들어지는가?
```

## 61. 마지막으로 한 번에 정리

리뷰 흐름:

```txt
pending review가 있으면 앱 시작 시 review로 이동한다.
ReviewScreen은 useReviewScreen이 관리하는 queue의 첫 항목을 보여준다.
승인/거절 제출 후 pending-reviews와 launch-flow를 무효화한다.
리뷰가 끝나면 main/start로 이동하고 완료 토스트를 띄운다.
```

랭킹 흐름:

```txt
현재 선택 그룹 기준으로 ranking query를 실행한다.
멤버를 누르면 member todos를 조회하고 certification viewer를 연다.
랭킹 source로 인증 상세를 열면 readTodo를 호출하고 ranking query를 갱신한다.
```

통계/인증 목록 흐름:

```txt
통계는 현재 그룹 기준 statistics query를 실행하고 chart summary를 계산한다.
인증 목록은 sort 기준으로 query하고 filter는 클라이언트에서 적용한다.
인증 목록 카드도 certification viewer를 통해 상세 화면으로 이동한다.
```

한 줄로 줄이면:

```txt
Dogether RN의 리뷰/랭킹/통계/인증목록은 인증 데이터를 중심으로 query key와 viewer store를 통해 서로 연결되는 후속 화면 흐름이다.
```
