# RN 실행방법 읽는 법

이 문서는 Dogether RN 프로젝트를 로컬에서 실행할 때 어떤 명령어를 써야 하는지 정리한 문서입니다.

이 프로젝트는 Expo 기반이므로 실행 명령은 대부분 `package.json`의 script를 통해 시작합니다.

```bash
npm run start:mock
npm run start:dev
npm run ios:dev
npm run android:dev
npm run test
```

처음에는 아래 한 줄만 기억하면 됩니다.

```text
서버 없이 화면만 확인하고 싶다 -> mock
개발 서버 API와 붙이고 싶다 -> dev
운영 서버 API와 붙이고 싶다 -> prod
```

---

## 1. 먼저 확인할 파일

실행 방법을 볼 때는 아래 파일을 먼저 확인하면 됩니다.

| 파일 | 보는 이유 |
| --- | --- |
| `package.json` | 실제 실행 명령어가 들어 있음 |
| `app.config.ts` | 앱 이름, bundle id, native plugin 설정 확인 |
| `src/config/env.ts` | 앱 안에서 환경변수를 어떻게 읽는지 확인 |

`package.json`의 `scripts`가 실행 진입점입니다.

```json
{
  "scripts": {
    "start:mock": "... expo start",
    "start:dev": "... expo start",
    "start:prod": "... expo start",
    "ios:dev": "... expo run:ios",
    "android:dev": "... expo run:android",
    "test": "npm run typecheck"
  }
}
```

---

## 2. 설치

처음 프로젝트를 받은 뒤에는 의존성을 설치합니다.

```bash
npm install
```

이 프로젝트는 Expo, React Native, TypeScript, React Query, Zustand, MMKV 등을 사용합니다.

의존성 설치가 끝나면 `node_modules`가 생기고, `npm run ...` 명령을 사용할 수 있습니다.

---

## 3. 실행 환경 종류

Dogether RN에는 크게 세 가지 실행 환경이 있습니다.

| 환경 | 의미 | API 주소 | Mock 사용 |
| --- | --- | --- | --- |
| `mock` | 서버 없이 목 데이터로 실행 | `https://api-dev.dogether.site` | 사용 |
| `dev` | 개발 서버 API로 실행 | `https://api-dev.dogether.site` | 기본 미사용 |
| `prod` | 운영 서버 API로 실행 | `https://api.dogether.site` | 미사용 |

이 값들은 `package.json` script에서 환경변수로 주입됩니다.

예를 들어 `start:dev`는 대략 이런 값을 넣고 Expo 개발 서버를 켭니다.

```text
APP_ENV=dev
EXPO_PUBLIC_APP_ENV=dev
EXPO_PUBLIC_API_BASE_URL=https://api-dev.dogether.site
EXPO_PUBLIC_USE_MOCK_API=false
```

앱 내부에서는 `src/config/env.ts`가 이 값들을 읽어서 `env` 객체로 정리합니다.

```text
process.env.EXPO_PUBLIC_APP_ENV
-> src/config/env.ts
-> env.appEnv
-> repository factory / API client / 화면 로직에서 사용
```

Expo에서 JS 코드가 읽어야 하는 환경변수는 `EXPO_PUBLIC_` 접두사가 붙어야 합니다.

---

## 4. 개발 서버만 켜기

Expo 개발 서버만 켜고 싶으면 `start:*` 명령을 사용합니다.

| 명령어 | 의미 |
| --- | --- |
| `npm run start:mock` | 목 데이터 기반으로 Expo 개발 서버 실행 |
| `npm run start:dev` | 개발 API 기반으로 Expo 개발 서버 실행 |
| `npm run start:prod` | 운영 API 기반으로 Expo 개발 서버 실행 |
| `npm run start` | 별도 환경 주입 없이 `expo start` 실행 |

가장 안전한 첫 실행은 mock입니다.

```bash
npm run start:mock
```

이 명령을 실행하면 터미널에 Expo Dev Server가 뜹니다.

그 다음 선택지는 보통 세 가지입니다.

```text
i
-> iOS Simulator에서 열기

a
-> Android Emulator에서 열기

QR 스캔
-> 실제 기기에서 열기
```

다만 이 프로젝트는 Kakao 로그인, MMKV처럼 네이티브 기능과 가까운 라이브러리를 사용하므로 Expo Go만으로는 제한이 있을 수 있습니다.

그럴 때는 `ios:*`, `android:*`처럼 development build를 만드는 명령을 사용하는 편이 더 정확합니다.

---

## 5. iOS 실행

iOS Simulator나 iOS development build로 실행하려면 `ios:*` 명령을 사용합니다.

| 명령어 | 의미 |
| --- | --- |
| `npm run ios:mock` | iOS 앱을 mock 환경으로 빌드/실행 |
| `npm run ios:dev` | iOS 앱을 개발 서버 API 환경으로 빌드/실행 |
| `npm run ios:prod` | iOS 앱을 운영 서버 API 환경으로 빌드/실행 |
| `npm run ios` | 별도 환경 주입 없이 `expo run:ios` 실행 |

개발 API와 붙여서 iOS에서 확인하려면 보통 이 명령을 씁니다.

```bash
npm run ios:dev
```

서버 없이 화면과 흐름만 보고 싶으면 mock으로 실행합니다.

```bash
npm run ios:mock
```

운영 API와 붙여야 할 때는 prod를 사용합니다.

```bash
npm run ios:prod
```

`expo run:ios`는 필요하면 `ios/` 네이티브 프로젝트를 생성하거나 사용해서 앱을 빌드합니다.

---

## 6. Android 실행

Android Emulator나 Android development build로 실행하려면 `android:*` 명령을 사용합니다.

| 명령어 | 의미 |
| --- | --- |
| `npm run android:mock` | Android 앱을 mock 환경으로 빌드/실행 |
| `npm run android:dev` | Android 앱을 개발 서버 API 환경으로 빌드/실행 |
| `npm run android:prod` | Android 앱을 운영 서버 API 환경으로 빌드/실행 |
| `npm run android` | 별도 환경 주입 없이 `expo run:android` 실행 |

개발 API와 붙여서 Android에서 확인하려면 보통 이 명령을 씁니다.

```bash
npm run android:dev
```

서버 없이 확인하려면 mock입니다.

```bash
npm run android:mock
```

운영 API와 붙여야 할 때는 prod를 사용합니다.

```bash
npm run android:prod
```

Android는 실행 전에 Android Emulator가 켜져 있거나 실제 Android 기기가 연결되어 있어야 합니다.

## 7. Web 실행

이 프로젝트에는 web 실행 스크립트도 있습니다.

```bash
npm run web
```

내부적으로는 아래 명령입니다.

```bash
expo start --web
```

다만 Dogether RN은 모바일 앱 기준으로 작성되어 있고, 네이티브 모듈을 사용하는 기능이 있으므로 web에서는 모든 기능이 똑같이 동작하지 않을 수 있습니다.

화면 구조를 빠르게 보는 용도로 생각하는 것이 좋습니다.

---

## 8. 개발 서버와 운영 서버

여기서 말하는 개발 서버와 운영 서버는 Expo 개발 서버가 아니라, 앱이 호출하는 백엔드 API 서버를 의미합니다.

```text
Expo 개발 서버
-> JS bundle을 기기나 시뮬레이터에 전달하는 로컬 개발 서버

개발 API 서버
-> https://api-dev.dogether.site

운영 API 서버
-> https://api.dogether.site
```

명령어 이름으로 보면 이렇게 구분할 수 있습니다.

```text
start:dev / ios:dev / android:dev
-> 개발 API 서버 사용

start:prod / ios:prod / android:prod
-> 운영 API 서버 사용
```

운영 API에 실제 데이터가 연결되어 있다면 `prod` 실행은 조심해서 사용해야 합니다.

---

## 9. Mock 실행

mock 환경은 서버 없이 앱 흐름을 확인할 때 사용합니다.

```bash
npm run start:mock
npm run ios:mock
npm run android:mock
```

mock 환경에서는 `EXPO_PUBLIC_USE_MOCK_API=true`가 들어갑니다.

이 값은 repository factory에서 실제 API 구현체 대신 mock repository를 선택하는 데 사용됩니다.

```text
env.useMockApi === true
-> Mock Repository 사용

env.useMockApi === false
-> API Repository 사용
```

화면 개발 중 서버 상태와 관계없이 UI를 확인하고 싶을 때 가장 편합니다.

---

## 10. Dev 실행

dev 환경은 개발 백엔드 서버와 붙여서 앱을 확인할 때 사용합니다.

```bash
npm run start:dev
npm run ios:dev
npm run android:dev
```

dev 환경에서는 기본적으로 실제 API repository를 사용합니다.

```text
EXPO_PUBLIC_APP_ENV=dev
EXPO_PUBLIC_API_BASE_URL=https://api-dev.dogether.site
EXPO_PUBLIC_USE_MOCK_API=false
```

다만 `package.json`을 보면 일부 항목은 개별 mock flag를 따로 끌 수 있게 되어 있습니다.

```text
EXPO_PUBLIC_USE_MOCK_APP_INFO=true
EXPO_PUBLIC_USE_MOCK_AUTH=false
EXPO_PUBLIC_USE_MOCK_GROUPS=false
EXPO_PUBLIC_USE_MOCK_CHALLENGE_GROUPS=false
EXPO_PUBLIC_USE_MOCK_USER=false
EXPO_PUBLIC_USE_MOCK_REVIEW=false
```

즉 전체는 실제 API를 쓰되, 특정 영역만 mock으로 바꾸는 구조도 가능합니다.

---

## 11. Prod 실행

prod 환경은 운영 백엔드 서버와 붙여서 앱을 확인할 때 사용합니다.

```bash
npm run start:prod
npm run ios:prod
npm run android:prod
```

prod 환경에서는 아래 값이 들어갑니다.

```text
EXPO_PUBLIC_APP_ENV=prod
EXPO_PUBLIC_API_BASE_URL=https://api.dogether.site
EXPO_PUBLIC_USE_MOCK_API=false
```

`app.config.ts` 기준으로 prod는 앱 이름과 bundle id에 suffix가 붙지 않습니다.

```text
prod
-> 앱 이름: dogether-RN
-> bundle id/package: com.ujhong7.dogether
```

반면 dev/mock은 suffix가 붙습니다.

```text
dev
-> 앱 이름: dogether-RN Dev
-> bundle id/package: com.ujhong7.dogether.dev

mock
-> 앱 이름: dogether-RN Mock
-> bundle id/package: com.ujhong7.dogether.mock
```

이렇게 나누면 dev/mock/prod 앱을 같은 기기에 따로 설치해서 비교할 수 있습니다.

## 12. 테스트와 타입 체크

현재 이 프로젝트의 테스트 명령은 TypeScript 타입 체크입니다.

```bash
npm run test
```

내부적으로는 아래 명령을 실행합니다.

```bash
npm run typecheck
```

`typecheck`는 다시 아래 명령입니다.

```bash
tsc --noEmit
```

뜻은 다음과 같습니다.

```text
TypeScript 타입 오류를 검사한다.
실제 JS 파일은 생성하지 않는다.
```

현재 `package.json`에는 Jest나 React Native Testing Library로 작성된 unit test 실행 스크립트는 따로 없습니다.

그래서 이 프로젝트에서 "테스트 돌린다"는 말은 현재 기준으로 "타입 체크를 돌린다"에 가깝습니다.

## 14. 처음 실행할 때 추천 순서

처음에는 아래 순서가 무난합니다.

```text
1. npm install
2. npm run test
3. npm run start:mock
4. iOS라면 npm run ios:mock
5. Android라면 npm run android:mock
6. 서버 연동이 필요해지면 ios:dev 또는 android:dev
```

서버 연결이나 로그인 SDK 설정에 막히면 먼저 mock 환경으로 화면 흐름을 확인하고, 그 다음 dev 환경으로 넘어가는 것이 좋습니다.

---

## 한 줄 정리

```text
start:* 는 Expo 개발 서버를 켜는 명령이고,
ios:* / android:* 는 실제 플랫폼 앱을 빌드해서 실행하는 명령이며,
mock/dev/prod 는 앱이 어떤 API 환경을 바라볼지 정하는 값이다.
```
